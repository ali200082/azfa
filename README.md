# AZFA Web — تطبيق إدارة الطلاب على المتصفح

تطبيق ويب يفتح من الموبايل أو الحاسبة عبر المتصفح، ويستخدم **نفس قاعدة بيانات Firebase** الخاصة بالبرنامج الأصلي — أي البيانات مشتركة ومتزامنة بين البرنامج المكتبي وتطبيق الويب.

> ⚠️ هذا المشروع منفصل تماماً عن `azfa_advanced.py`، ولم يُمَس البرنامج الأصلي.

## التشغيل السريع (Windows)
انقر نقرًا مزدوجًا على **`تشغيل.bat`**

سيقوم بـ:
1. إنشاء بيئة Python افتراضية تلقائياً
2. تثبيت المتطلبات (Flask, requests)
3. تشغيل السيرفر على `http://localhost:5000`

## التشغيل اليدوي
```powershell
cd "C:\تطبيق ويب"
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

## الفتح من الموبايل
1. وصّل الموبايل والحاسبة بنفس شبكة الواي فاي.
2. على الحاسبة، شغّل التطبيق.
3. شوف عنوان IPv4 المطبوع في النافذة (مثلاً `192.168.1.10`).
4. على الموبايل، افتح المتصفح واكتب: `http://192.168.1.10:5000`
5. اضغط "إضافة إلى الشاشة الرئيسية" لتثبيته مثل التطبيقات.

## المميزات
- 📱 واجهة محدثة ومتجاوبة — لوحة متابعة، قائمة جانبية، وجداول وبطاقات للموبايل
- 🔄 مزامنة مباشرة مع نفس Firebase الذي يستخدمه البرنامج الحالي
- 🗂️ إدارة الدورات الدراسية وتسجيل الطلاب وربط حسابات الأساتذة
- ✅ حضور ودرجات وتقارير مرتبطة بالدورة المختارة، مع الحفاظ على السجل العام القديم
- 👨‍🏫 تسجيل بدء وانتهاء محاضرات الأستاذ ورابط Meet، مع عرض وإدارة تقارير الحضور للمدير والمطور
- 💾 تنزيل نسخة JSON احتياطية لبيانات المدرسة والدورات (لا تتضمن كلمات المرور)
- 🌐 PWA — يثبت على الموبايل بأيقونة وشاشة كاملة
- 🔍 بحث + فلاتر (مستوى/كروب)
- ➕ إضافة/تعديل/حذف الطلاب
- 🛡️ Fallback تلقائي لرابط Firebase البديل

تسجيل الدخول يبدأ بكتابة اسم المدرسة أو رمزها، ثم اسم المستخدم وكلمة المرور.
يتحقق النظام من الحساب داخل المدرسة المحددة ويطبّق دور الحساب وصلاحياته
(مدير أو أستاذ) من Firebase؛ لا تظهر شاشة اختيار المدرسة بعد دخول الحساب.

الدورات تستخدم المسارات المشتركة مع البرنامج المكتبي:
`schools/<school_id>/courses` و`enrollments` و`course_settings`.
اختيار الدورة النشطة في الويب خاص بجلسة المتصفح، ولا يغيّر الدورة النشطة المحفوظة محلياً في البرنامج المكتبي.

## تحديث وتشغيل خادم Render

ملف `render.yaml` يجهّز الخدمة باسم `azfa-web` ويشغّلها بواسطة Gunicorn على Python 3.11.
بيانات الطلاب والدورات محفوظة في Firebase، لذلك لا تحتاج إلى ترحيل قاعدة البيانات عند نشر هذا التحديث.

1. شغّل الاختبارات محلياً، ثم ارفع التغييرات إلى الفرع المرتبط بخدمة Render:
   ```powershell
   .\.venv\Scripts\python.exe -m unittest discover -s tests -p test_course_web.py
   git add app.py templates static tests README.md
   git commit -m "Update AZFA web features and interface"
   git push origin main
   ```
2. إذا كان النشر التلقائي مفعّلاً، انتظر اكتمال النشر من تبويب **Events** في Render.
   وإلا افتح الخدمة في Render ثم **Manual Deploy → Deploy latest commit**.
3. راجع **Logs**؛ يجب أن يبدأ Gunicorn دون أخطاء. افتح رابط الخدمة وتحقق من تسجيل الدخول،
   اختيار المدرسة، صفحة الدورات، والحضور والتقارير.
4. قبل استخدام الدورات في العمل الفعلي، نزّل نسخة احتياطية من **الدورات والتسجيلات → تنزيل نسخة احتياطية**.

إذا كان الخادم منشوراً من مستودع مختلف أو على فرع غير `main`، ارفع التغييرات إلى الفرع الذي تعرضه إعدادات **Settings → Build & Deploy → Branch** في Render بدلاً من `main`.

## تحديث PythonAnywhere

إذا كان الموقع يعمل على PythonAnywhere، ارفع التغييرات إلى GitHub أولاً، ثم افتح
**Consoles → Bash** في الحساب. انتقل إلى مجلد التطبيق الفعلي (المعروض في **Web → Code**)
وشغّل `git pull origin main`. إذا كان للتطبيق virtualenv محدد في تبويب **Web**،
فعّله وثبّت المتطلبات منه، ثم ارجع إلى **Web** واضغط **Reload**. لا تنشئ Web App
جديداً عند تحديث التطبيق الموجود.
